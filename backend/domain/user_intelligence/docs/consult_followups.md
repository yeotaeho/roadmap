# 상담실(AI 상담) 후속 과제 — SP-9 트랙 (미착수·설계 보류)

2026-07-04 기록. 실사용 대화 검토에서 드러난 상담실 3공백을 순차 보강하는 트랙. 지금은 **설계만 남기고 코드 이연** —
이유는 아래 "선행 의존성"에 정리한다. 관련: [상담실 리디자인 스펙](../../../docs/superpowers/specs/2026-07-04-consult-redesign-langgraph-interview-design.md)(SP-8).

## 배경 — 3공백

| # | 공백 | 지금 | 있어야 할 것 |
|---|------|------|------|
| ① | 자기모델이 대화에 반영 안 됨 | 상담사 맥락에 페르소나+시장 섹터만 주입(`build_consult_context`), 자기모델 미주입 | 파악한 RIASEC·Big Five·서사를 배경 기억으로 읽어 활용 |
| ② | 진행·완료가 사용자에게 안 보임 | 라운드 완료가 조용히 성향 지도만 리페치 | 커버리지 진행률·완료 알림 UI |
| ③ | 로컬에서 즉시 추출 불능 | Windows 로컬은 체크포인터 fail-open → 커버리지 턴마다 리셋 → 라운드 완료 불가 → 즉시 추출·`self_model_updated` 미발동 | 운영 Linux 검증 + 로컬 폴백(커버리지 내구화) |

## 선행 의존성 — ③이 먼저다 (중요)

①·②는 **자기모델 데이터가 실제로 채워져야** 체감·검증된다. 그런데 현재:
- 로컬(Windows)은 체크포인터가 상시 fail-open이라 커버리지가 턴마다 리셋 → 11축 라운드가 **구조적으로 완료 불가** → 즉시 추출이 영영 안 돎.
- 일일 10:00 배치만 자기모델을 채우므로, 배치 전에는 `user_self_model`이 비어 있음.

따라서 ①(자기모델 주입)을 지금 구현해도 **주입할 데이터가 없어 end-to-end 검증이 불가**하다. 순서를 **③ → ①·② 로 재정렬**하는 것을 권장한다(원래 사용자 요청 순서 ①→②→③에서 조정). ③으로 추출이 안정적으로 돌게 된 뒤 ①·②를 얹어야 실제로 동작을 확인할 수 있다.

### ③ 후보 방향 (SP-8a 이월과 통합)
- **운영 Linux 검증** — `AsyncPostgresSaver`가 Docker/Linux에서 인터뷰 커버리지를 실제로 지속하는 통합 경로를 확인(현재 CI 미검증).
- **로컬 폴백(커버리지 내구화)** — 체크포인터가 없어도 커버리지가 리셋되지 않게: 커버리지를 `consult_sessions`의 JSONB 컬럼(또는 기존 요약 옆)에 별도 영속하거나, plan 노드가 매 턴 **자기모델의 기존 신호로 커버리지를 시드**(이미 축이 파악됐으면 covered로 간주). 후자는 ①과도 시너지(이미 아는 축은 안 물음).
- SP-8a 이월 동반 재조명 — 강등 트리거 과광범위(노드 예외도 체크포인터 영구 비활성)·단일 커넥션 직렬화→`AsyncConnectionPool`.

## ① 설계 초안 (숨은 배경 기억 — 사용자 확정)

- **톤 결정**: 숨은 배경 기억 — 파악한 성향을 사용자에게 **단정하지 않고**, 이미 파악된 축은 다시 안 묻고 더 깊은 질문·개인화에만 활용(발견 과정 유지).
- **데이터 흐름**: `_load_context_system`이 매 턴 `get_self_model(user_id, include_sensitive=False)`를 추가로 읽어 `self_model_memory()` 직렬화 블록을 시스템 프롬프트에 append(읽기 실패 시 생략).
- **직렬화 `self_model_memory(model) -> str`** (user_intelligence 도메인 내, market_insight 미import): **신호 있는 축만** — 흥미(`riasec.top_codes` 라벨)·성격(Big Five 뚜렷한 축 강점/중립 서술어, 신경성=정서안정성)·`narrativeSummary`. 셋 다 없으면 빈 문자열(초기 all-50 노이즈 방지).
- **프롬프트 지침 한 문장**: "'지금까지 파악한 당신'은 잠정적 배경 기억이다. 단정하지 말고, 이미 파악된 축은 다시 캐묻지 말며, 더 깊은 질문·개인화에만 활용하라."
- **경계**: 자기모델 읽기 전용·민감 근거 미주입. SP-8c 계약과 정합(상담사도 raw 대화 아닌 정제층을 읽음).

## ② 설계 초안 (진행·완료 가시화)

- 커버리지(11축 중 몇 축 파악)를 프론트에 노출 — SSE로 턴마다 `coverage` 요약을 보내거나, 성향 지도 패널에 진행률 표시.
- 라운드 완료 시 채팅/패널에 "성향 파악이 정리됐어요" 알림(현재는 조용한 리페치만).
- ③ 이후에 얹어야 진행률이 실제로 오른다(커버리지가 리셋되면 진행률도 무의미).

## 상태

**보류(deferred)**. 다음 상담실 작업 시 **③부터** 착수 권장. 이 문서가 설계 출발점.
