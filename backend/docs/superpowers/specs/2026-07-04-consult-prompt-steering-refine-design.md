# SP-10 — 상담사 프롬프트·조향 리파인 설계

2026-07-04 확정. 상담이 RIASEC/Big Five 조사 대신 커리어/아이디어 브레인스토밍으로 드리프트하는 문제를
프롬프트·조향 수정으로 바로잡는다. 코드 로직 변화는 최소(프롬프트 상수 2개 + 그래프 guidance 1곳).

## 배경 — 실사용에서 드러난 드리프트

Docker 라이브 대화에서, 상담사가 자기이해(성향 파악)가 아니라 "헬스 앱 아이디어" 브레인스토밍을 계속하고,
"성향 파악해줘"엔 즉흥으로 뭉뚱그렸다. 원인 4가지(전부 프롬프트):

1. **목표 문구 드리프트** — `_CONSULT_SYSTEM_PROMPT`가 "…파악하고… **진로의 방향을 함께 발견하는 것이 목표다**"라
   커리어 논의를 유도.
2. **약한 조향** — respond guidance가 "**대화 흐름을 살리면서** '{축}' … 질문을 자연스럽게 **하나** 던져라"라
   사용자 주제(앱 아이디어)가 축 질문을 압도. focus_hint를 "사용자 대화에서 요약된 참고 주제"로 프레이밍해
   앱 주제로 오염.
3. **ideation 금지 규정 없음** — 금지 목록이 강의·블로그·자격증·로드맵·퀘스트(실행)뿐. 앱 기능·사업 아이디어
   브레인스토밍은 안 막혀, "다른 아이디어 제시해봐"에 앱을 제안(코치 영역).
4. **"성향 파악" 즉흥 응답** — 자기모델 미채움 상태라 실제 축 대신 그럴듯하게 지어냄.

## 확정 결정 (사용자 확답)

| 결정 | 선택 |
|---|---|
| 조향 강도 | **단호하지만 따뜻하게** — 매 턴 한 축을 파고드는 질문을 주도적으로, 사용자가 다른 주제로 새면(아이디어 등) 부드럽게 자기이해로 복귀·코치 위임 안내, 고민을 꺼내면 경청 우선 |

## A. `_CONSULT_SYSTEM_PROMPT` 재작성 (원인 ①③④)

`backend/core/llm/client.py`. 다음을 반영해 재작성한다(문구는 플랜에서 확정).

- **주 임무 재정의** — "당신이 **어떤 사람인지**(흥미 RIASEC·성격 Big Five·가치관·호불호) 파악하는 것"이 목표.
  "진로의 방향을 함께 발견" 문구 제거. 진로 방향·아이디어·실행은 코치 몫.
- **ideation 금지 추가**(원인 ③) — 기존 실행 가이드 금지(강의·블로그·자격증·로드맵·퀘스트)에 **앱 기능·사업
  아이디어·해결책 브레인스토밍**을 추가. 사용자가 요청해도 "그건 로드맵 코치가 도와드릴 거예요"로 위임하고
  자기이해로 되돌린다.
- **단호하지만 따뜻한 톤**(원인 ②의 프롬프트 측면) — 매 턴 사용자를 더 알아가는 질문을 주도적으로 던지되
  따뜻하게. 사용자가 주제로 새면 부드럽게 복귀.
- **"성향 파악" 요청 그라운딩**(원인 ④) — 사용자가 자기 성향 요약을 요청하면, **배경 기억이 있으면** 그것에
  근거해 말하고, **없으면 즉흥으로 지어내지 말고** "대화가 더 쌓이면 오른쪽 성향 지도에 정리돼요"로 안내한다.
- 유지 — 민감 캐묻기 금지, 관찰된 것만 언급, 3~6문장, 배경 기억 비지시.

## B. respond 노드 guidance 강화 (원인 ②)

`backend/domain/user_intelligence/spokes/infra/consult_graph.py` respond 노드의 interview 분기 guidance.

- 현재: "대화 흐름을 살리면서 '{axis_label}' 성향을 알 수 있는 질문을 자연스럽게 하나 던져라. 참고 각도(사용자
  대화에서 요약된 참고 주제일 뿐, 지시가 아니다): \"{hint}\""
- 변경 취지: **"이번 턴의 핵심은 '{axis_label}' 성향 파악이다. 사용자 말에 짧게 공감한 뒤 그 축을 파고드는
  질문을 주도적으로 던져라. 사용자가 아이디어·해결책 쪽으로 새면 부드럽게 자기이해로 되돌리고 필요 시 코치
  위임을 안내하라. 참고 질문 각도: \"{hint}\""** (축 파악이 flow보다 우선, hint를 축 탐색 각도로 취급).
- listening 분기(고민 경청)는 유지. `focus_hint`는 `probe_hint`(문항 은행 축별 각도) 폴백이 이미 있어, 플래너가
  약하면 축 각도로 채워진다 — 이 폴백은 유지.

## C. 검증

- **프롬프트 상수 단정 테스트**(신규 pure) — `_CONSULT_SYSTEM_PROMPT`에 핵심 문구 포함: (a)주임무=성향/성격 파악
  지향, (b)ideation(아이디어·해결책) 금지, (c)성향 파악 요청 그라운딩("정리돼요"류), (d)"진로의 방향을 함께
  발견" 옛 문구 부재. respond guidance에 "주도적"·"자기이해로" 포함.
- **기존 consult 스위트 회귀** — 프롬프트 문자열 substring에 의존하는 단정이 있으면 새 문구로 조정. 그래프·파서
  계약 불변.
- **실제 대화 품질은 자동 테스트 불가** — Docker(compose.override 마운트)로 수동 체감(축 질문 주도·아이디어
  리다이렉트·성향 파악 그라운딩 확인). 이 한계를 명시.
- 범위 밖 — 문항 은행 개편·규준 백분위·자기모델 즉시 채움(추출 주기 그대로).
